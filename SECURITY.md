# Security and privacy

Agent Arcade has an independent **local hook observer** and two optional WeChat execution methods. The observer never approves commands or reads full transcripts. **API mode** starts an app-managed SDK run; **local mode** relays to the user's original interactive Claude Code CLI. Both can relay single-use decisions from the paired owner. Reply text is not opened as a URL or executed as an application command. The original CLI and SDK can execute tools under their respective permission rules.

Saved API/WeChat credentials use Electron OS encryption without plaintext fallback. Connections are opt-in with no startup replay/resume; only the paired owner's complete fresh text is accepted. API mode has a bounded serial queue, expiring task-bound codes and a fail-closed hook/host callback for every tool. Its cancellation invalidates requests and waits for execution to settle. These controls are not an OS sandbox: approved Windows commands may affect other files or the network. Use a disposable project for acceptance; do not expose this as a multi-user service.

API mode gives the SDK an API key, a small OS-environment allowlist, isolated configuration, disabled ambient hooks/plugins/MCP and subprocess credential scrubbing. Local mode does not read/copy Claude login credentials or set an API key; the user authenticates in the unmodified CLI. Existing CLI permissions and user/project behavior remain relevant, while MCP servers are restricted by the generated launch config. Read or previously allowed operations may not prompt again. Local permission fields are upstream previews; masked/omitted/oversized previews are refused remotely. A sent verdict does not prove it was adopted before a local decision.

Local mode opens a temporary capability-authenticated HTTP broker bound to 127.0.0.1. The 256-bit capability and a per-attachment ID bind its requests; sequence gaps and uncertain MCP writes close the relay rather than replay input silently. The capability is in a private per-connection MCP config, not OS-encrypted, and is revoked on close; cleanup attempts to remove that config. This file contains neither Claude nor WeChat credentials, and the renderer/copied command receives only its path. This is not protection against another process running as the same OS user. Keep portable runtime paths alive while the original CLI uses them; generate a fresh command after reconnecting.

Local `/cancel` pauses new forwarding and sends pending denials; disconnect/quit revokes the relay but cannot guarantee stopping the independent CLI or a running tool. Stop execution in its own terminal with Ctrl+C. Messages may combine in one turn, so message/reply/permission records cannot be treated as verified per-task execution. Tencent/model data flow and separate SDK/original CLI session retention are in [WECHAT.md](docs/WECHAT.md). No exactly-once delivery or durable queue is promised. A heuristic redactor is not a general secret detector.

Renderer isolation: context isolation and sandbox enabled, Node integration disabled, navigation/new windows denied, permission requests denied, narrow validated IPC, no remote assets. Themes are validated palette/grid data, not SVG imports, HTML, or scripts. Response text is rendered using `textContent`.

The local inbox is not a security boundary against another process running as your user. Files use owner-only POSIX modes where supported and inherit user-directory ACLs on Windows. Stored results are not encrypted. The installer refuses malformed settings and keeps a backup before every change. It installs only observational command hooks. Tool inputs are transiently hashed using a random local HMAC key for permission correlation, then discarded. Do not include `observer-key`, real settings, or captured replies in public support reports.

For a vulnerability, use GitHub's private vulnerability reporting if enabled. If unavailable, open an issue asking for a private reporting channel without including exploit details or sensitive data. Do not post credentials or real transcripts in public issues.

Preview builds are unsigned. Verify the release source, build status and SHA-256 hashes, or build from source. No automatic updater is included.
