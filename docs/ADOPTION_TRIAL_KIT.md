## 本候选的集中操作入口与回退

现在不关闭现有 App，也不打开真实档案。主人安排集中验收时，先核对整合报告的文件 SHA-256，再手动挂载 DMG／解开 ZIP；不要覆盖现有安装，先保留旧 App。不要同时启动两个副本：单窗口守卫会返回既有应用。安装、Gatekeeper 与钥匙串授权由主人按实际系统提示判断，未公证包不承诺可直接分发；不移除 quarantine 或放宽钥匙串 ACL。

本轮测试已触发 `agent-arcade-integrated-… Safe Storage` 的系统授权弹窗。这些是专用假密钥测试项目；脚本已停止真实钥匙串调用。**“始终允许”一个 ad-hoc 副本不保证覆盖不同 CDHash 的下一副本。** 不以重复点允许作为通过；主人已授权并固定本机个人签名身份，冷构建与相同签名要求已验证；首次真实档案换签仍需另行验收。直接调用 Keychain API 也受同一授权约束。

回退时先退出本次候选，保留当前试验档案副本，再按 [UPDATE_BACKUPS](UPDATE_BACKUPS.md) 核对 manifest：完整 root／WAL／SHM 与原映射位置一起恢复，不能只复制一个 SQLite 文件。旧 App 与匹配的完整旧档案配套回退。文件备份不备份系统钥匙串加密密钥，换 Mac 或签名授权失败不能靠复制 vault 保证恢复。所有实际恢复仅在主人批准的试验档案执行。

## 可直接使用的反馈问题

首次使用反馈：

1. 你拿到的候选标识、系统／架构是什么？从开始到首条回复约多久？
2. 哪一步卡住？你原以为会发生什么、实际发生什么？是否需要别人指出下一步或代操作？
3. 你是否试了查看／更正／忘记记忆、停用来源／暂停提醒？哪些成功、失败或没找到？请只描述合成例子。
4. 与你平时使用的办法相比，有什么具体步骤省下或增加了？目前你会选哪个办法，为什么？不知道也可。
5. 若愿意补充，仅提供去除账号／key／私聊／私人路径后的错误类别与截图；不需要发完整聊天或日志。

D7 回访先问：

1. 在收到这次回访之前，你有没有主动再次打开？大约哪天、为了做什么？如只是为求助或测试要求打开，请说明。
2. 记忆或提醒有没有一次让你继续选择它，或者让你放弃？具体发生了什么？没有也照实写。
3. 如果没有回来，最大的原因是什么？继续用原办法是否更方便？
4. 你是否愿意继续用这个候选？最先需要修什么？不继续或不想接受后续联系均可。

每个问题允许跳过；反馈不要求证明付费、提供身份或暴露私人关系。停止试用时关闭测试来源／App，不用删除整个数据目录；有需要时由本人保留备份并按对应候选说明处理。
