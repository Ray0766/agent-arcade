## Resources, latency and charges

- **No invented local VRAM minimum.** The reviewed Qwen/CosyVoice setup pages do not establish a guaranteed Windows memory requirement for our clip length/concurrency. For scale only, nominal 0.6B and 1.7B FP16 parameter tensors are about 1.2 and 3.4 GB before codec, cache, buffers and runtime; these arithmetic figures are not peak-VRAM requirements. Measure cold start, resident memory and generation with one active voice first. ASR and TTS need not run concurrently across all three accounts.
- **Qwen's 97 ms is not our latency.** The [Qwen3-TTS report, section 3.4](https://arxiv.org/html/2601.15621v1#S3.SS4) reports 97 ms for 0.6B and 101 ms for 1.7B at concurrency one using an internal vLLM V0 engine, compilation and CUDA Graph optimization. It is first synthesis packet timing, excluding our microphone endpointing, chat model and playback chain. The current [vLLM-Omni serving documentation](https://docs.vllm.ai/projects/vllm-omni/en/latest/user_guide/examples/online_serving/text_to_speech/#streaming-pcm) now supports actual Qwen3-TTS raw PCM streaming with async chunking; Qwen's README description of offline-only vLLM integration is stale. This does not make the installed `qwen-tts` Python wrapper streaming, and [vLLM does not officially support native Windows](https://docs.vllm.ai/en/stable/getting_started/installation/gpu/index.html?device=cuda). Linux/WSL deployment and local latency remain separate work. Likewise CosyVoice's advertised 150 ms is an author claim for its streaming pipeline, not a measured Windows guarantee.

The subsequent local experiments used official CUDA 12.8 wheels in isolated Python 3.11 environments, without FlashAttention or WSL. The owner selected the 1.7B **Serena** sample as 橘娘's voice reference. A bounded native-Windows [latency comparison](../outputs/voice-comparison/latency/README.md) preserved that WAV bit-for-bit: one-thread warm whole-sentence inference took 9.754 seconds versus default 24-thread 13.159 seconds in one run each. Separately generated sentences made first PCM available at 3.542 seconds but would leave a 3.616-second gap if played immediately. The warm codec-generation stage accounted for over 99% of synthesis time; PCM decoding took about 0.03 seconds. This improves a baseline but does not establish smooth real-time speech. The Qwen TTS model remains an audition baseline; the later running optional pipeline uses GPT-SoVITS with its selected synthetic reference. The comparison receipts, selected audio and model revision remain preserved; genuine spoken interruption and broader ASR quality remain unaccepted beyond the single later owner-confirmed neural manual run.
- **A native NVIDIA path exists, but is not the default choice.** Its [Qwen3 TTS pack](https://docs.nvidia.com/ace-for-games/qwen-tts/1.0/getting-started.html) offers Windows CUDA/Vulkan/D3D12 inference. The [published RTX 4090 English benchmark](https://docs.nvidia.com/ace-for-games/qwen-tts/1.0/nvigi-developer-pack.html) reports CUDA mean 164 ms to first codec codes, explicitly not first PCM playback and excluding model loading. Chinese conversation and this machine remain untested; NVIGI integration/runtime distribution also needs separate review. Do not introduce that stack merely for a headline latency number.
- **Local inference has no per-minute API charge**, but downloads, storage, GPU memory/power and maintenance remain real costs. The FunASR reference HTTP wrapper starts a new binary per request, so it is a prototype path rather than a demonstrated low-latency resident service. [Pinned runtime design](https://github.com/modelscope/FunASR/blob/runtime-llamacpp-v0.2.6/runtime/llama.cpp/README.md).
- **Cloud price snapshot, not an account quote:** the official CNY table checked 2026-11-05 lists Beijing `qwen3-asr-flash` at CNY 0.00022/audio-second and `qwen3-tts-flash` at CNY 0.8/10,000 input characters; their realtime variants are CNY 0.00033/second and CNY 1/10,000 characters. Singapore rates differ (ASR 0.00026/second, realtime ASR 0.00066/second; TTS 0.733924 and realtime TTS 0.954101/10,000 characters). Do not assume a free quota, transfer another provider's credits or equate input characters with spoken seconds. Recheck the chosen account/region before enabling billing. [Pricing](https://help.aliyun.com/en/model-studio/model-pricing).

## Acceptance before choosing a default

Use the same owner-approved short Mandarin, mixed-language and proper-name utterances for each ASR, with editable output and no automatic sends. Report actual correction count and CER only when a reference transcript exists. For TTS, use identical character text and volume, hide candidate names during owner listening where practical, and collect pronunciation, pauses, emotional fit and preference. Record cold/warm first audible PCM, full-turn delay, stop-to-silence and stale-output suppression separately. No universal latency/quality ranking is established by this review.

Whichever speech engine wins must retain account/panel ownership, single-use draft submission, cancellation, bounded audio/text buffers, no cross-account playback and local/private evidence defaults. A model change cannot by itself complete the still-unaccepted human interruption flow. See [current voice behavior](VOICE_AND_CHARACTER_CARDS.md) and [nine-feature acceptance](COMPANION_ACCEPTANCE.md).

Fish's [Community License](https://github.com/fishaudio/fish-speech/blob/main/LICENSE) allows limited commercial use below USD 500,000 annual revenue, with attribution and other conditions. Its separate Hosted Service provision explicitly excludes an application's own generated assistant replies; it must not be misreported as prohibiting every companion app. The [S2-Pro weight license](https://huggingface.co/fishaudio/s2-pro/blob/main/LICENSE.md) separately requires a license for commercial use. These distinctions matter for future distribution; neither should be described as unrestricted MIT/Apache software. A hosted Fish API would also introduce independent service terms, billing and outbound text/reference handling.

For interaction design, [AIRI](https://github.com/moeru-ai/airi) offers an MIT, TypeScript/WebAudio-oriented example of separating character presentation, listening and multi-provider speech; borrow those boundaries, not its entire avatar stack. [Open-LLM-VTuber](https://github.com/Open-LLM-VTuber/Open-LLM-VTuber) is a useful reference for hands-free conversation and interruption, but its MIT code does not cover the separate [Live2D sample terms](https://github.com/Open-LLM-VTuber/Open-LLM-VTuber/blob/main/LICENSE-Live2D.md), and its README announces an early v2 rewrite while v1 receives fixes. Avoid a wholesale dependency on that moving architecture. [Pipecat's BSD-2-Clause code](https://github.com/pipecat-ai/pipecat) provides concrete [output interruption/buffer clearing](https://reference-server.pipecat.ai/en/latest/_modules/pipecat/transports/base_output.html) and [turn detection](https://github.com/pipecat-ai/docs/blob/main/api-reference/server/utilities/turn-detection/smart-turn-overview.mdx) references: stop generation and pending playback together, and distinguish silence from a completed thought. Adapt these contracts to our Electron/Node pipeline rather than replacing it with a Python framework. None of these references completes our human interruption acceptance or fixes ASR simply by changing TTS.
