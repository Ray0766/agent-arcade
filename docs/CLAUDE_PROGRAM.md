# Local Claude program mode

Current source, 2026-11-04. The owner selected this route for Ju after a real no-tool probe succeeded with the existing original Claude Code login. It removes the custom Channels startup step by using a different official CLI entry point; it does not auto-confirm a Channels warning or skip tool permissions. The published `0.3.0-preview.2` binary still uses the older Channels route.

## Connect

1. Install the original Claude Code CLI and sign in through its own login flow. The original direct/QQ checks used **2.1.317**; a later WeChat check observed **2.1.318** through original CLI auth status. The app does not collect or copy Claude credentials.
2. Choose **Local Claude · program mode** and check the original CLI login before configuring the chat channel. No extra API key, **Open Claude** action or custom-channel confirmation is used by this mode.
3. Select a project, then configure WeChat ClawBot or the [personal QQ bridge](QQ.md) and start receiving messages. AI authentication and chat pairing are separate prerequisites; neither alone proves a model round trip.

Keep the computer and Agent Arcade running. The app launches a hidden original CLI process for each dispatched turn. A separate interactive terminal does not need to stay open. If the CLI login expires or is unavailable, complete login in the original CLI; the app cannot sign in for you. Existing installations are not automatically switched from Channels or given a new Claude conversation.

## Processing and authority

The path is messaging transport → existing Dispatcher → original `claude --print` subprocess → Dispatcher → messaging transport. Mode `claude` is separate from legacy `native` (Channels) and `api` (Claude Agent SDK with an API key). QQ identity, owner gating, message deduplication and persona selection remain independent of the execution route.

The runner uses structured `stream-json` stdin/stdout, an explicit new session UUID or `--resume` UUID, and the stdio permission/control messages described by the installed **Claude Agent SDK 0.3.317** types. It spawns the user's unmodified CLI directly; it does not invoke SDK `query` or route subscription tokens through the app. This control-protocol dependency needs compatibility checks after CLI upgrades; a minimum-version check alone is not evidence that every later release works. Initialization must confirm registered fail-closed hooks before a user prompt is sent.

The launch explicitly uses empty `--setting-sources` and strict empty MCP configuration, disables slash commands, and does **not** use `--bare` or the development Channels flag. Authentication comes from the original CLI's usual profile; the child environment does not inject API keys, OAuth tokens, provider overrides or a replacement `CLAUDE_CONFIG_DIR`. This intentionally differs from opening an unrestricted interactive terminal with ambient project/user settings and MCP servers. It is not an operating-system sandbox.

Known tools are Read, Glob, Grep, Edit, Write, Bash and AskUserQuestion. A fail-closed PreToolUse hook asks for each action; unknown tools are denied. The existing Dispatcher presents one-time approvals and questions in chat. Plain assent, quoted text and expired codes cannot approve an action. The runner returns the original approved input without permanent permission updates and invalidates requests cancelled by the CLI. Ordinary chat without tools returns its text directly.

Each turn is bounded to **24 turns of the agent loop and ten minutes**, with bounded protocol frames/output. There is no API dollar-cost cap in this local mode; the original account's limits and billing apply. A successful result is labeled `reply_ended`, not verified task success.

## Conversation, stop and recovery

- Within one connection, completed turns continue the exact recorded session UUID. `/new` clears the Dispatcher conversation reference; it does not delete original Claude transcripts.
- `停止` or `/cancel` cancels queued work and pending approvals, requests interruption, then checks process exit. The runner may force-stop its own subprocess tree if graceful interruption does not finish. An unconfirmed stop remains an error, not a claim that execution ended.
- Disconnect closes the owned executor. File changes already made are not rolled back, and independent background jobs are not confirmed stopped.
- The original CLI may persist conversation transcripts in its own profile. Agent Arcade does not move historical Channels conversations into this mode. An application restart does not automatically resume a model conversation or replay prior input; SQLite preserves receipt deduplication and interrupted metadata only.

## Why this route

The prior Channels integration delivered messages into an interactive Claude terminal and required a development-channel confirmation on every startup. That constraint belongs to Channels, not every CLI entry point. The [official programmatic CLI guide](https://code.claude.com/docs/en/headless) documents `-p`, structured results, specific-session continuation and permission hosts. Program mode can therefore fit the same chat-first workflow as the local Codex adapter without keeping an interactive terminal open.

A documented MCP permission tool is an alternative to stdio control. The selected stdio route reuses the control contract already shipped with the locked SDK package and avoids another permission-server process. It requires more protocol handling than SDK `query`; no latency, memory or reliability advantage has been measured. The API/SDK route remains available for users who want separate API authentication, and legacy Channels remains selectable for compatibility.

Authentication boundaries are separate from technical execution. Current [product-use terms](https://code.claude.com/docs/en/legal-and-compliance#can-customers-offer-claude-code-in-their-products) discuss running the unmodified original CLI with each user's own authentication. The same page's [credential-use section](https://code.claude.com/docs/en/legal-and-compliance#authentication-and-credential-use) and [SDK quickstart](https://code.claude.com/docs/en/agent-sdk/quickstart#setup) restrict third-party claude.ai login/credential routing and direct SDK products toward API authentication. This project keeps login in Anthropic's flow and does not treat one successful local test as blanket authorization for every distribution or hosted service. Sources checked 2026-11-04.
