## Character cards

`src/bot/character-cards.cjs` imports UTF-8 JSON files up to 64 KiB in Agent Arcade's `arcade_character_v1`, Character Card V2, or Character Card V3 envelopes. The supported presentation subset is a name, public description/personality/scenario, up to six user/character speaking examples, and author/version/license metadata. An import must be previewed before applying it. Existing original portraits are selected by catalog ID; remote artwork, external assets, scripts, tools, system prompts, lorebooks and extensions are not imported. Greetings never send automatically. This is bounded field compatibility, not a complete SillyTavern runtime or PNG/CHARX importer.

Speaking examples illustrate style, not real private conversation or authority. They use at most 240 characters per side. Combined public description/personality/scenario must fit the app's 800-character description limit; oversized cards fail with an editing instruction rather than silently truncating identity. `cardToSettings()` produces only presentation settings and `cardFromSettings()` exports only those fields. Private history, memory, contact IDs, API keys, proactive permissions and backend selection are excluded.

Own-format exports preserve the original portrait ID and all supported metadata. The desktop export button currently uses this own format; the module also supports V2/V3 JSON exports with empty system instructions, greetings and extensions, and a creator-note license label when provided. Other applications may interpret a card differently. A supplied license label is the author's claim; importing a card does not establish redistribution rights for its text or artwork.

The implementation uses independently written parsing against the [Character Card V3 specification](https://github.com/kwaroran/character-card-spec-v3/blob/main/SPEC_V3.md), checked on 2026-11-05, and the existing [SillyTavern reference review](TECH_RADAR.md). No SillyTavern code or downloaded character art was copied in that first version. Later AGPL-3.0 adaptations are recorded in `src/vendor/sillytavern/README.md`.

`src/voice/windows-speech.cjs` starts a hidden, application-owned Windows PowerShell host containing fixed bundled C# source. It loads the Windows .NET Framework `System.Speech` assembly. Input is bounded JSON over stdin, never shell code. It does not modify execution policy, system speech settings or model credentials. There is no added package, speech API key or model download.

The host uses an installed `SpeechRecognitionEngine` with `DictationGrammar` and the default microphone. It uses `SpeechSynthesizer` and an installed voice for output. Recognized text goes to the selected existing companion model; normal model costs still apply. The app does not record, save or upload audio. Recognized text and the answer enter the selected relationship's local conversation memory.

The latest source default is **开始说话 / Start speaking → 说完了 / Finish speaking → edit recognized text → 发送 / Send**. Opening or locating the voice panel never opens the microphone. Finishing uses [`RecognizeAsyncStop`](https://learn.microsoft.com/en-us/dotnet/api/system.speech.recognition.speechrecognitionengine.recognizeasyncstop) to complete the current recognition, with a five-second finish limit, then enters an editable review. Only explicit Send submits its single-use draft to the model and memory. Rerecording, incoming QQ activity, closing or changing account invalidates the old draft. Empty text makes no model request. The owner can listen for up to ten minutes before the fallback limit; no externally started 30-second response window is required. The original manual package submitted directly on Finish; the subsequently launched reviewed package contains the explicit editable review/Send step. Launch is established, while its real voice review/quality flow remains unaccepted.

Starting again interrupts the previous model call and playback. **Interrupt** cancels recognition, the current model request and playback. The optional **Hands-free with headphones** mode keeps recognition active and cancels the active response when the recognizer detects new speech. Headphones are explicitly required because this SAPI path does not implement reliable speaker echo cancellation. Ambient sounds may interrupt playback; dictation quality depends on the installed language, microphone and speech. A spoken “停止”/“停一下”/“别说了”/“暂停”/“stop” stops the current reply without sending that command to the model. Listening closes after at most ten minutes and is never resumed automatically after app restart. Actual recognition and heard interruption remain unaccepted.

Every response has a generation number and abort signal. Late model results and late speech-host events from a cancelled generation are discarded. Account and panel identifiers bind controls to the originating voice session, so a late close/interrupt from an older panel cannot stop a newer one. Switching account/character or disconnecting closes the old voice session and microphone. The response callback uses `SocialCompanion.respondLocally()` rather than injecting a fake QQ message or sending the same reply through QQ. Incoming QQ activity cancels old local generation and playback; voice has no additional tool access. These lifecycle rules have automated tests, with real account-switch and incoming-message interruption still awaiting acceptance.

Input diagnostics aggregate the recognizer's [AudioLevelUpdated event](https://learn.microsoft.com/en-us/dotnet/api/system.speech.recognition.speechrecognitionengine.audiolevelupdated) once per second, retaining up to 120 numeric level samples, never PCM or recordings. No speech onset after 15 seconds produces an input hint without forcing an immediate submit; the manual sequence uses the ten-minute listening limit above. After closing, the latest redacted diagnostic session remains exportable per account (up to six accounts in memory), with the close reason retained. Account/panel/selection checks keep another character's diagnostics from appearing in the current voice panel. Settings and the numeric meter are collapsible. This makes the current recognition failure inspectable without treating microphone-open as success.

Native interfaces verified against Microsoft's current documentation on 2026-11-05: [speech engine and audio input](https://learn.microsoft.com/en-us/dotnet/api/system.speech.recognition.speechrecognitionengine), [free-text dictation](https://learn.microsoft.com/en-us/dotnet/api/system.speech.recognition.dictationgrammar), and [cancelling asynchronous speech synthesis](https://learn.microsoft.com/en-us/dotnet/api/system.speech.synthesis.speechsynthesizer.speakasynccancelall). The shipped Windows .NET Framework implementation is used; documentation may display a newer prerelease NuGet version, which this app does not install. Windows-only availability is explicit. If no recognizer or microphone is available, text conversation remains usable and the user is directed to Windows speech/microphone settings.
