The newer AI-first package has separately passed isolated onboarding/provider UI checks; fresh sign-in, its live message flow and program-mode WeChat stop/recovery remain unverified at this checkpoint.

The earlier **Channels** route remains available for compatibility. One controlled Windows/current-account Channels flow passed ordinary chat, actual Write, allow/deny, stopping a running process tree and same-session recovery. AI and channel selection are independent: source also contains local Codex, GPT API and DeepSeek API adapters, whose own authentication and tool limits apply. Source availability does not establish a real WeChat round trip for each backend. Keep the existing Electron interface and original role assets.

## Setup

1. From a clean clone, install Node.js 22.13+, run `npm ci`, then `npm start`. A Windows portable includes its application/API runtime; local Claude still requires the separately installed original CLI. Direct/QQ program-mode checks used **Claude Code 2.1.317**; the later WeChat run observed **2.1.318** through original CLI auth status. The compatibility Channels route additionally requires system Node.js 22.13+. The terminal hook observer is optional for the bridge.
2. Prepare the AI before the chat channel. For local Claude, complete login through the original CLI, then choose **Local Claude · program mode**. For an API backend, enter that provider's own key in the app and check it before connecting. A saved key or original CLI login status is not proof of successful model execution. See [Claude program mode](CLAUDE_PROGRAM.md), [Codex](CODEX.md), [GPT API](GPT.md) and [DeepSeek API](DEEPSEEK.md). The revised packaged AI-first screen passed isolated UI checks, not a fresh real-account sign-in test.
3. Select a disposable project. On your phone, open **WeChat → Me → Settings → Plugins → ClawBot**. If this entry is unavailable, account/client compatibility is unresolved; an ordinary friend chat is not a substitute. Tencent's [official channel guide](https://intl.cloud.tencent.com/zh/document/product/1316/84459), checked 2026-11-04, describes the ClawBot entry and lists iOS 8.0.70+; [another official release record](https://cloud.tencent.com/document/product/213/130654) also lists Android QR support. A complete availability matrix and Windows WeChat minimum version remain unverified.
4. In Agent Arcade's connection settings, choose **WeChat → Pair WeChat**. Scan this application's QR code and confirm on the phone. This implementation uses Tencent's text protocol directly; the OpenClaw installation command on the phone page is for OpenClaw users, not an Agent Arcade installation step. A successful pairing saves Tencent authorization credentials. The destination is the **ClawBot conversation**, not a newly created ordinary friend. The upstream [maintainer explicitly distinguishes this from personal-account friend messaging](https://github.com/Tencent/openclaw-weixin/issues/52#issuecomment-4407647606). Pairing that requires an additional unsupported phone-verification flow remains unresolved.
5. Start receiving messages only after the selected AI, project and chat account are ready. Keep the computer/app running and send a fresh ordinary chat message. Pairing alone never starts execution. Changing from old Channels to program mode does not import the old model conversation or replay earlier tasks.
6. For task acceptance, request a small text file in that disposable project, inspect the actual file locally, and check the WeChat reply. Also test refusal, stopping and reconnecting for the selected mode. A model-generated report is not independent verification.

The desktop distinguishes **credential saved**, **channel online with no inbound text**, and **inbound text received**. The outbound count means Tencent accepted a send request, not that the recipient read it. An empty successful poll cannot prove an incoming task or final reply was delivered. Confirm a real round trip and inspect the actual output before calling setup accepted.

For DeepSeek, the [official first-call guide](https://api-docs.deepseek.com/) requires a provider API key. Its [model-list endpoint](https://api-docs.deepseek.com/api/list-models/) can check access and whether the chosen model is listed without generating a conversation; the [balance endpoint](https://api-docs.deepseek.com/api/get-user-balance/) separately reports whether the balance supports API calls. Neither result verifies a chat reply or local file operation. Agent Arcade does not turn a DeepSeek website login into an API credential. Sources checked 2026-11-04.

## Local Claude · program mode

Mode `claude` runs the unmodified original `claude --print` process behind the same Dispatcher used by the API modes. It needs the user's original CLI login, not an Anthropic API key. Ordinary chat can reply directly without tool approval; known file/command tools require a current one-time approval. It uses explicit session IDs within a connection, with bounded turns and runtime; it does not inherit historical Channels sessions. `停止` requests interruption and confirms the owned process exit; a failed exit check remains an error. `/new` clears the current conversation when idle. See [protocol, authentication and stop limits](CLAUDE_PROGRAM.md).

The program runner and Ju's real QQ path passed their [separate acceptance](evidence/claude-program-qq-20261104.json). The later [WeChat receipt](evidence/claude-program-wechat-20261104.json) establishes a narrower program-mode flow: retained pairing without a new QR scan, ordinary chat with zero tool approvals, one approved Write and a delivered path. Independent readback matched **24 bytes**, SHA-256 `271663ff1827609919f23a77313ee59a4d7024760a4954d17a56ec488859ea26`. The target was absent before the single approval. Original CLI auth status observed version **2.1.318** and method `claude.ai`; the app did not read or copy its credentials.

Compared with the earlier Channels startup, this run needed **zero Channels startup confirmations** while retaining real file permission. No overall efficiency improvement was measured. It used the `claude-program-preview` packaged runner. The newer onboarding package separately passed isolated checks, including simulated retained WeChat pairing without a rescan and required account/project configuration; `outputs/onboarding-packaged.json` and `outputs/providers-packaged.json` explicitly mark synthetic data and no live accounts/models. New login/expired credentials, live delivery through that newer package, program-mode WeChat denial, stop, long-running cancellation and outage recovery remain unaccepted; the older Channels evidence below does not establish them.

## Claude API agent

This remains a separate app-managed SDK workflow. Save your own Anthropic API key in the password field, then select **Start receiving tasks**. Never paste a key into an issue, task message, screenshot or chat. API calls incur charges; this mode does not use claude.ai subscription login. DeepSeek and GPT API use their own provider keys and runner limits, not these Claude SDK settings.

One task runs at a time, with three queued tasks. Later prompts use this connection's explicit SDK session ID. Every tool action, including reads, requires a five-minute, single-use confirmation: type `同意 CODE` or `拒绝 CODE`; `/allow CODE` and `/deny CODE` remain supported. No permanent allow rule is written. `停止` or `/cancel` aborts the run and clears the queue; execution must settle before a replacement starts. `/new` starts fresh when idle. A single question accepts `/answer CODE text`, or a plain answer when it is the only pending request. `状态` or `/status` can resend a pending request and retry the latest failed final delivery within the same connection.

Tasks are capped at 6,000 characters, 24 SDK turns and ten minutes. The SDK cost threshold defaults to USD 1 and can be set from USD 0.05 to 5; it is not a hard billing cap and in-flight calls may exceed it. Parameters larger than 3,000 UTF-8 bytes or containing recognized secret patterns are refused rather than shortened. Inspect the project for full output if a reply is visibly shortened.

**Windows shell tools:** API mode exposes `Bash` and file tools, so install [Git for Windows](https://gitforwindows.org/) for shell tasks. Direct Read/Write/Edit tasks do not need Git. Current Claude Code itself can [use native PowerShell without Git](https://code.claude.com/docs/en/setup#set-up-on-windows), but `PowerShell` is not in this mode's fixed tool list. Local mode uses the installed CLI's own tool set. Project-specific tools such as npm remain separate prerequisites.

## Legacy local Claude Code Channels

Legacy mode `native` uses [official Claude Code Channels](https://code.claude.com/docs/en/channels) with your own unmodified interactive CLI. It is optional compatibility behavior, not the new program-mode setup. Agent Arcade does not read, collect or copy Claude login credentials, and does not set an API key for this mode. Authentication, account limits and billing follow the original CLI. Log in there through Anthropic's own flow first; do not paste its credentials into Agent Arcade.

1. Install system Node.js 22.13+ and Claude Code 2.1.317+, select **Local Claude Code CLI**, then **Connect WeChat / 连接微信**. No Agent Arcade API key is needed; a previously saved key remains stored for later API use.
2. Choose **Open Claude / 打开 Claude** in the conversation settings. On Windows, Agent Arcade opens a visible original-CLI console in the selected project and records its exact process identity and generated session UUID. It uses `--allowedTools mcp__agent-arcade-wechat__reply --permission-mode default --strict-mcp-config --mcp-config <private file> --dangerously-load-development-channels server:agent-arcade-wechat`, plus `--session-id <UUID>` for a new conversation. Only this session's exact WeChat reply tool is pre-allowed; no permanent allow setting or user/project MCP setting is written. No permission-skipping flag is used. Existing deny/ask rules, hooks and organization policy still apply; see the [CLI flag](https://code.claude.com/docs/en/cli-reference) and [MCP permission syntax](https://code.claude.com/docs/en/permissions#mcp). Copying the manual launch command remains a fallback, but the app cannot claim ownership or stop authority over a manually started process.
3. Personally review the CLI's custom development-channel and project/MCP trust prompts. Channels is a **research preview**; this WeChat channel is not on the default approved allowlist. The development flag enables this local test entry; it does not skip tool permissions. It is interactive only: `-p` or the Agent SDK cannot silently load this development channel. See the [official startup contract](https://code.claude.com/docs/en/channels-reference#test-during-the-research-preview).
4. Keep that terminal and Agent Arcade open while work runs, then send a fresh message in ClawBot. MCP initialization only proves a local process connected. Confirm a real reply before treating the route as usable. Use `停止` to request stopping an app-owned session; after it stops, `恢复会话` or the desktop's **Resume last session / 恢复上次会话** opens that project's recorded UUID with `--resume`. Complete any original-CLI prompts before sending new work. Resume does not replay missed input or verify task success.

Messages can be combined while the CLI is busy; one WeChat message is not guaranteed to be a separate task or response boundary. The `reply` tool must name a current forwarded message ID, but a reply does not mean the whole CLI turn ended or the work passed tests. The original hook observer can separately display real session events.

Successful native forwarding sends no receipt acknowledgement to WeChat. Agent replies return as their bounded, privacy-filtered body, without a fixed “task result / outcome unverified” prefix. The channel asks the agent to answer ordinary conversation naturally and report meaningful failures or unperformed checks when relevant. Permission requests and actionable transport errors still appear. MCP/forward/reply counters are in the desktop's **Connection details**, not added to routine chat. Removing boilerplate does not turn a reply into independent task verification.

Local mode follows the CLI's own permissions: reads or previously allowed operations may run without a new prompt. A permission requiring approval can be relayed as a **CLI parameter preview** with a six-character code: type the displayed `同意 CODE` or `拒绝 CODE` line. The slash-command equivalents remain supported. It belongs to the CLI session, not necessarily one WeChat message. The upstream preview may be normalized or masked; app-detected omitted, redacted, unserializable or oversized previews are denied remotely and should be checked locally. A sent verdict does not prove it won the race with a local decision or was applied. See [permission relay semantics](https://code.claude.com/docs/en/channels-reference#relay-permission-prompts).

## Conversation — Claude API and legacy Channels

This table describes the retained older routes. Program mode uses the Dispatcher commands described above and in [CLAUDE_PROGRAM.md](CLAUDE_PROGRAM.md); it does not use the legacy `恢复会话` terminal reopening behavior.

| Message | Claude API agent | Legacy Claude Channels |
| --- | --- | --- |
| Plain text | One queued SDK task | Forwarded session input, silently on success; may be combined with other messages |
| `状态` or `/status` | Task/queue; resend pending request; can retry latest failed final send | Connection/pending-request summary and resend; no model-state or delivery guarantee |
| `同意 CODE`, `拒绝 CODE` or `/allow CODE`, `/deny CODE` | Decide one pending SDK action | Send one verdict for a current relayed CLI request; adoption unconfirmed |
| `/answer CODE text` | Answer the identified single question | Unsupported; use normal conversation or the original CLI |
| `停止` or `/cancel` | Abort run, clear queue, invalidate approvals | Pause input/deny pending requests; force-stop this app instance's verified CLI process tree. Manual/unowned processes are only paused at the relay |
| `恢复会话` or `/resume` | Unsupported | Explicitly reopen the recorded project/session UUID after the previous process is confirmed gone; no input replay |
| `/new` | Fresh app-managed session when idle | Handle a new session in the original CLI |

The managed Windows stop checks the captured PID, UTC process creation time and executable path before targeting that process tree, then verifies that its main process exited. This is **force termination, not a graceful task cancellation or rollback**: file changes already made remain, and independent/detached jobs or external effects are not confirmed stopped. Each newly launched process sets `CLAUDE_CODE_DISABLE_BG_EXIT_HANDOFF=1` locally; this does not prove every external job is under its tree. If the user backgrounds the session themselves, an attach client exiting is not evidence that its background agent stopped. Process exit, reply end and task success remain separate facts.

For a manually opened CLI, an app restart that lost process ownership, or an unconfirmed process identity, use **Ctrl+C in the original terminal** and inspect remaining work. The app never kills all Claude processes or adopts a PID from saved metadata. Normal disconnect attempts to stop a currently owned process and revokes the relay/codes; a crash or failed stop can leave execution running. There is no automatic model-session resume or replay.

Only one selected execution mode consumes this app's WeChat connection. Switch while disconnected; the API key is retained. The displayed six-character aliases expire after five minutes and are single use. Eight wrong short-code attempts temporarily block short-code lookup for five minutes; `状态` resends the complete request with a compatible full 128-bit nonce when blocked. A resend keeps the original request, code and expiry; it does not extend permission. Sending a current short code alone while a request is pending prompts for `同意 CODE`/`拒绝 CODE` and resends the request; it neither approves nor becomes a task. Plain “好的”, voice transcription and quoted commands never authorize an operation. Bot messages are currently Chinese; the desktop supports English and Chinese. Supplied voice transcription and bounded quoted text are accepted as text; images, audio decoding, attachments and group tasks are unsupported. Local stop cannot withdraw already executed actions or enforce the API mode's turn/time/cost limits.

## Privacy, restart and failure

The local HTTP broker, generated MCP configuration and captured interactive-process metadata below apply to **legacy Channels** only. Program mode owns a per-turn CLI subprocess instead; its credential, settings and cancellation boundaries are in [CLAUDE_PROGRAM.md](CLAUDE_PROGRAM.md).

- The observer stays local. The bot sends messages/results through Tencent and model input through the selected AI provider or local CLI. No app analytics are added; Claude API-mode SDK nonessential traffic is disabled. Original CLI data policies still apply; program mode deliberately excludes ambient settings and MCP servers rather than loading the Channels configuration.
- API key and WeChat token use Electron's OS credential encryption in `~/.agent-arcade/bot-vault.json`. The renderer receives only connection flags, never those credentials. There is no plaintext fallback. This Windows-first preview has not accepted other platform vault backends.
- Execution mode/project/cost configuration is in `bot-config.json`. Bot history is bounded and memory-only. API mode separately persists SDK sessions under `~/.agent-arcade/bot-agent/`; local mode retains the original CLI's normal session storage. The observer's result-capture switch does not control either. Forgetting credentials does not delete model sessions or project files.
- `native-process/<workspace hash>.json` stores that project's session UUID and captured PID/creation time/executable metadata for explicit resume. It stores no conversation or credential and never grants a restarted app ownership of the old process. Missing, corrupt or uncertain identity fails closed rather than launching a duplicate or stopping another session.
- Local mode opens a random-port **127.0.0.1-only HTTP broker** with a temporary 256-bit capability, a per-attachment ID and bounded events. Its private `~/.agent-arcade/native-launch/<random ID>/mcp.json` contains the loopback address/capability so the CLI can spawn the Node channel. This temporary capability is not OS-encrypted; it is not a Claude or WeChat credential, is never shown in the copied command, and is revoked when the relay closes. The app attempts to remove the file on disconnect. Old commands/files cannot reconnect a revoked broker. Another process running as your local user is outside this security boundary.
- Packaged Node channel code and production dependencies are unpacked from ASAR so system Node can load them. Keep the app open while using its generated command; portable extraction paths may disappear after exit. Regenerate the command on every new connection instead of saving it as a permanent launcher.
- There is no auto-connect, auto-replay or auto-resume after restart. Messages older than the new connection are ignored; resend a task after reconnecting. Missing/late messages may be dropped. There is no exactly-once delivery claim or durable task queue.
- Network failures use bounded retries. After the first temporary local-channel poll failure, the stdio relay keeps the same client/cursor for up to 30 seconds, with exponential backoff capped at two seconds and each request bounded by the remaining window. This is not a guarantee for every WeChat/network outage. Expired authorization requires pairing again. A stream gap, uncertain MCP write, invalid response or revoked capability closes the relay rather than replaying input. A normal channel exit attempts detach; a killed/crashed process may only be detected by the broker's 90-second lease. An unstarted or manually launched connection expires after five minutes. While the app keeps verifying that its own Claude process is running, it renews only the pre-attachment startup lease so waiting at the original CLI prompt does not force a restart. Attached clients still expire after 90 seconds without a heartbeat; unknown process identity does not renew the startup lease. This does not approve or bypass the CLI prompt. API `/status` can retry a failed final send within the same connection; local mode does not promise that behavior. After disconnect/restart, inspect the project and any remaining CLI before retrying.
- **Native Windows execution is not an OS sandbox.** A selected `cwd` is a starting location, not filesystem containment. Approved commands may read, change or transmit other data. API mode excludes ambient OAuth/project hooks/plugins/MCP from its SDK environment. Local mode uses your original CLI's login and user/project behavior, with MCP servers restricted to the generated config; it does not copy the API-mode isolated environment onto your native session.
