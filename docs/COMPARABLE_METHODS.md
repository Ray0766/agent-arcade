## 采用的三种方法

### 按用户下一步区分平台与版本

参考 TT 的平台和发布渠道分层，借鉴的是“先判断拿到了什么，再给下一步”。Agent Arcade 将公开旧版、固定开发源码、后续本地候选分别指向对应说明，并以提交与包哈希识别候选；入口落点是 [FIRST_RUN](FIRST_RUN.md) 和 [CANDIDATE_STATUS](CANDIDATE_STATUS.md)。没有可下载 Mac 候选资产就明确写没有，不用本地路径、CI artifact 或相同版本号代替公开版本。

预期减少选错版本、跟错说明的返工，尚未测得改善幅度。之后用同一候选记录陌生人“辨认版本→找到适用说明→启动”的耗时、错误入口和求助次数；源码安装与现成安装包分别记录，不把 clone 时间当首条回复时间。不因此新增移动端、包管理器分发或自动更新系统。

### 导入前告知范围，导入后核对结果

参考 TT 迁移脚本的输入检查、执行范围和结果位置告知，转化为本项目的**有限导入核对单**，不新建全量迁移功能：

| 操作者核对 | Agent Arcade 当前边界／应记录证据 |
| --- | --- |
| 确认来源与目标 | 只用自制无敏感 PNG／JSON 角色卡或其他已明确支持的单项导出；记录格式、目标角色与候选身份。源文件保留。 |
| 看支持与忽略项 | 按[移植表](SILLYTAVERN_PARITY.md)逐项核对；CHARX、第三方扩展加载器、脚本及全量 ST 聊天档案不能写成支持。预设的忽略字段和世界书的不支持选项不得省略。 |
| 应用前确认 | 使用候选已有的预览／警告；没有预览时如实记录，先在空白测试档案验证，不虚构按钮。陌生内容不能获得执行或账号权限。 |
| 应用后核对 | 比较角色描述、示例、支持字段与警告；可导出时再对照。导入成功不等于该信息已进入模型上下文，也不证明模型风格正确。 |
| 失败后回退 | 停止本次导入，保留原文件与错误分类；恢复时仅处理试验档案，先关闭 App，再使用对应候选已有的恢复方法。不得覆盖真实聊天来尝试修复。 |

记录完成该有限任务的步骤数、人工改字段数、忽略项是否可理解、失败能否回到原状态。TT 的整档案复制、插件、跨设备同步和完整兼容承诺不采用，也不复制其角色／声音资产。

### 把“存了、选了、发了、答对了”分开

参考 ST 的上下文检查方法，先用现有代码和脱敏报告定位记忆问题，不新增管理 UI：

| 层次 | 应核查的问题 | 证据边界 |
| --- | --- | --- |
| 保存 | 指定角色是否存有当前事实与修订？拒绝记忆时是否没有新增结构化事实？ | 保存不等于下一轮检索；拒绝结构化保存不等于删除聊天。 |
| 选择 | 该轮使用了正确角色、事实／笔记来源、开关和预算吗？ | 命中项、版本与未命中原因要可区分；相同词命中不证明同义召回。 |
| 构造上下文 | 受控 marker 是否出现在该轮生产 prompt，旧值与其他角色 marker 是否缺席？ | 必须检查该轮，不能用上一轮固定回复代替。报告可只含 marker 断言、长度和 hash。 |
| 供应商请求／结果 | 真实请求是否成功？模型在不含答案的问题下是否正确使用当前事实？ | 构造出的 prompt 不自动证明供应商收到；模型质量须另有获授权真实调用，不输出 key 或完整私聊日志。 |

固定更正、忘记、同义问法、切角色、重启和提醒控制案例及实际结果见 [COMPANION_CASES](COMPANION_CASES.md)。简单基线与产品使用相同案例、角色条件和预算；canned 输出只用于运行链路，**不证明回答质量**。本轮没有竞品模型输出可供打分，也不能据用例总数宣称比 ST／TT 记忆更准。

排查顺序是：确认保存／作用域，再检查开关、选择与预算，最后才判断模型回答。找到反例后修相应层；不据一次未命中引入向量数据库、全量扩展系统或管理界面。
